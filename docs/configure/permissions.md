# 权限与批准

Zeta 在执行工具前检查操作需要的能力、目标范围和当前策略。安全的只读操作通常可以直接运行，高风险或超出范围的操作会请求批准或被拒绝。

## 哪些操作会被检查

权限系统会区分以下能力：

| 能力 | 常见操作 | 需要关注什么 |
| --- | --- | --- |
| 读取 | 读取文件、搜索代码、检查状态 | 路径是否属于当前工作区 |
| 写入 | 编辑、创建、移动或删除文件 | 目标文件和可恢复性 |
| 执行 | 运行命令、测试或本地进程 | 命令参数、环境和可能的副作用 |
| 网络 | 下载依赖、访问网页或调用服务 | 目标地址和外发数据 |
| 外部系统 | 调用 MCP 或已连接应用的工具 | 账户、资源和是否会写入外部状态 |

同一工具在不同参数下可能得到不同决定。例如，读取工作区文件和读取工作区外的凭据目录不是同一种风险。

## 如何处理批准请求

批准前检查动作、目标和作用时间。一次性批准只适合当前操作，不应被理解为对后续所有相似命令的永久授权。

如果请求范围比任务需要的大，拒绝请求并要求 Agent 缩小目标。不要用更宽的权限解决路径、配置或工具选择错误。

## 工作区信任

工作区文件可以请求配置、Skills、Hooks 或 MCP 连接，但不能自行授予信任。未受信任的工作区使用受限行为。工作区规则可以保持或收紧安全要求，不能覆盖更高层策略来扩大权限。
